# FidoNet Messenger

Консольный мессенджер на C#, реализующий **FidoNet Packet System (FTS-0001)** с нуля. Без BinkP — используется классический EMSI-хендшейк и бинарные `.pkt` пакеты.

## Возможности

- **FTS-0001 пакеты** — бинарный формат `.pkt`, тип 2+
- **EMSI-хендшейк** (FSC-0056) — с прямым и обратным обменом
- **Netmail и Echomail** — с кладжами `AREA:`, `MSGID:`, `FMPT:`, `TOPT:`
- **Тоссер** — раскладка эх по папкам
- **Роутер** — маршрутизация через транзитные узлы
- **Bundle** — несколько пакетов в одной сессии
- **Outbound-очередь** — сообщения для offline-пиров
- **Профиль** — ник, сисоп, имя системы, адрес
- **Хаб-рассылка** — эха `LOCAL.CHAT` для общего чата
- **Несколько пиров** — с переключением через `/to`

## Требования

- .NET 8.0 SDK
- Windows / Linux / macOS

## Сборка

```bash
dotnet build -c Release
```

Исполняемый файл появится в:

```
bin\Debug\net8.0\fido.exe
```

## Быстрый старт

Нужно **три терминала**: один хаб и два клиента.

### Терминал 1 — Хаб

```bash
fido listen
```

Хаб слушает порт **24554**, принимает пакеты, раскладывает их по эхам и **рассылает всем известным пирам**.

### Терминал 2 — Клиент A

```bash
fido chat 127.0.0.1 24554 24555 2:5020/200
```

- `127.0.0.1` — хост хаба
- `24554` — порт хаба
- `24555` — порт, на котором клиент A слушает входящие
- `2:5020/200` — FTN-адрес клиента A

### Терминал 3 — Клиент B

```bash
fido chat 127.0.0.1 24554 24556 2:5020/300
```

Теперь A пишет сообщение — его видят и хаб, и B. B отвечает — его видят A и хаб.

## Конфигурация

### nodelist.txt

Положите в `bin\Debug\net8.0\` (рядом с `fido.exe`):

```
2:5020/100|Hub|Hub|127.0.0.1|24554
2:5020/200|ClientA|Vasya|127.0.0.1|24555
2:5020/300|ClientB|Petya|127.0.0.1|24556
```

Формат: `адрес|имя узла|сисоп|хост|порт`

### profile.txt

Создаётся автоматически при первом запуске:

```
Nick=Vasya
SysopName=Sysop
SystemName=MyFido
Address=2:5020/100
```

Ник меняется через `/nick`, сисоп через `/sysop`, имя системы через `/system`.

### peers.txt

Список известных пиров. Обновляется автоматически.

## Как это работает

### EMSI-хендшейк

1. Caller → `**EMSI_INQ`
2. Answerer → `**EMSI_REQ`
3. Caller → `**EMSI_DAT <адрес> SYS <система> ZYZ <сисоп> <CRC16>`
4. Answerer → `**EMSI_ACK`
5. Caller → `**EMSI_ACK`
6. Answerer инициирует обратный хендшейк (роли меняются)

После этого обе стороны знают адрес, имя системы и имя сисопа друг друга.

### Передача пакетов

Каждый пакет — бинарный `.pkt` (FTS-0001), упакованный в:

```
[4 байта — количество пакетов]
[4 байта — длина пакета 1][пакет 1]
[4 байта — длина пакета 2][пакет 2]
...
```

### Хаб-рассылка

При получении Echomail в эху `LOCAL.CHAT` хаб:

1. Сохраняет сообщение в `EchoAreaStore`
2. Пересылает **всем пирам**, кроме отправителя
3. Каждый клиент получает сообщение на свой порт

## Ограничения

- Нет шифрования и аутентификации (пароль в пакете есть, но не проверяется)
- Протокол передачи — упрощённый TCP length-prefixed, не XMODEM/ZMODEM
- Нет FTS-0001 CRC на уровне сообщений (только в EMSI)
- Нет поддержки JAM/SQMSG баз — только файлы `.msg`
- Нет автоматического поллинга по таймеру (только вручную `/poll`)
